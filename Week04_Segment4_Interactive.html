CPU side

Sampler → BatchSampler runs in the main process and generates shuffled index lists. Workers never decide order — they only execute __getitem__ for assigned indices.

Transfer

Pinned memory eliminates the staging copy. non_blocking=True makes the GPU read asynchronously via DMA while Python continues — the transfer is free.

GPU side

Target: SM% > 85%, sustained. GPU trains on batch N while N+1 transfers and N+2 loads. Zero idle time when the pipeline is tuned correctly.

Why Normalise?
Raw pixel values are in [0,1]. Neural networks train faster when inputs have mean≈0 and std≈1. Subtract the ImageNet mean, divide by std — channel by channel.
# ImageNet normalisation — always the LAST transform T.Normalize( mean=[0.485, 0.456, 0.406], # R, G, B means across 1.2M ImageNet images std =[0.229, 0.224, 0.225], # R, G, B standard deviations ) # normalised = (pixel_float - mean) / std → values roughly in [-2.5, 2.5] # Use YOUR dataset mean/std when NOT fine-tuning an ImageNet pretrained model

How much RAM does your DataLoader actually consume — and why does Docker crash without --shm-size?
Why /dev/shm matters

DataLoader workers place finished batches in shared memory (/dev/shm), a RAM-backed tmpfs. Each prefetched batch occupies it until the main process reads it. Docker defaults to 64 MB — just 1–2 ImageNet batches. The error appears as a cryptic worker crash, never "out of shared memory".

# Fix 1: docker run docker run --gpus all --shm-size=16g myimage python train.py # Fix 2: docker-compose.yml services: trainer: image: myimage shm_size: '16gb' # Fix 3: mount explicit tmpfs docker run --tmpfs /dev/shm:rw,size=16g myimage python train.py
